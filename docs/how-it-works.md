# How TrueFrame works

TrueFrame is a *layout* for the OverlayEditor plugin that ships with RivaTuner Statistics Server (RTSS). It does not inject anything itself: RTSS draws the overlay, and TrueFrame defines what is measured, how it is calculated and how it looks. All layouts are generated by [`tools/make_overlay.py`](../tools/make_overlay.py).

## Data sources

| Data | Source |
|---|---|
| GPU load, temperature, clock, power, VRAM | RTSS hardware abstraction layer (HAL: NVAPI / ADL / IGCL) |
| CPU load, busiest core, clock, power, temperature | HAL, with LibreHardwareMonitor (bundled with RTSS) as a fallback; HWiNFO, AIDA64 or Afterburner are used only if they happen to be running |
| RAM | HAL |
| Frame timing | PresentMon (bundled with RTSS), per frame |
| Main FPS number | RTSS's own frame rate counter (`<FR>`), live |
| Hardware names | RTSS macros `%GPU%`, `%VRAM%`, `%CPU%`, `%RAM%` |

Why not HWiNFO: it would be a second program to install and configure, and its free version disables shared memory support after 12 hours.

## Detecting frame generation

**Problem.** With frame generation the game presents several frames for every rendered one, so the presented frame rate is 2x to 4x higher than the real one. RTSS has no flag that says "frame generation is on".

**Observation.** With frame generation, PresentMon's present-to-present intervals (`msBetweenPresents`) become *bimodal*: each real frame is followed by k-1 very short gaps. Sorted, the last 1024 intervals look like this:

```
k = 1:  all intervals ~ T
k = 2:  50% short, 50% ~ T
k = 3:  67% short, 33% ~ T
k = 4:  75% short, 25% ~ T
```

**Algorithm.** Take percentiles of the last 1024 intervals and call an interval *short* if it is below 30% of the 90th percentile (p90 is always a "long" interval):

```
k = 1 + [p40 < 0.3*p90] + [p60 < 0.3*p90] + [p71 < 0.3*p90]
real FPS = presented FPS / k
```

p40, p60 and p71 sit just below the 50%, 67% and 75% boundaries, so each extra frame generation step flips exactly one more test. The brackets are shown only when k > 1.

**Why percentiles.** An earlier version used the standard deviation of the intervals, and a single one-second freeze was enough to fake a "frame generation" detection. Percentiles are rank based, so a few extreme frames cannot move them. The current method was checked on simulated frame sequences for k = 1 to 4, with and without stalls.

**Cost.** The buffer holds 1024 frames, so a change (frame generation switched on or off) is recognised after roughly 10 seconds.

## 1% Low

`1% Low = 1000 / p99(msBetweenPresents)` over the last 1024 presented frames. The classic RTSS 1%/0.1% low counters are only filled in benchmark mode, so they are calculated here directly. With frame generation, the slowest present intervals are the gaps between real frames, so the value stays close to the lows of the rendered frames.

## Frametime graph

The graph shows `msBetweenDisplayChange`: the time between frames that actually changed the picture on the screen. Present-to-present time zigzags between near-zero and full frame time under frame generation (the graph becomes a solid wall); display-to-display time is what the eye sees, with or without frame generation.

PresentMon reports frames with a variable lag (0.5 to 2.5 s according to the RTSS documentation) and in batches. Drawn as soon as data arrives, the graph jumps forward and stops. RTSS solves this with a fixed display delay: data is shown a constant time after it happened, which is longer than the worst reporting lag, so new frames arrive at an even pace. TrueFrame uses **3000 ms**, the value chosen by the RTSS author (`PM_DisplayDelay`), and refreshes PresentMon data every **16 ms** (`PM_RefreshPeriod`). The average (last 60 frames) and worst frame (last 300 frames) next to the graph use the same data, so they always match what the graph shows.

The scale is fixed at 0 to 50 ms (20 FPS floor), so spikes are comparable between games.

## Sizes and resolutions

RTSS lays out text in a grid whose cell size follows the font height. Each preset sets the font so that text is about 1.3% of the screen height:

| Preset | Zoom | Font height |
|---|---|---|
| 1080p | 1 | 14 px |
| 1440p | 1 | 19 px |
| 4K | 1 | 28 px |

The 4K preset uses zoom 1 with a larger font instead of zoom 2: the text looks the same, but the graph gets twice as many pixels, so it scrolls half as fast and shows a longer history.

## Hotkey

RTSS's HotkeyHandler stores the OSD toggle key in `Plugins\Client\HotkeyHandler.cfg` as one hex number: the low word is the Windows virtual key code, the high word holds modifiers (Shift = 1, Ctrl = 2, Alt = 4). Ctrl+Shift+F10 is `00030079`. The default avoids single F-keys (games and Steam use them) and plain Ctrl combinations (Ctrl is a game key in many titles; the tilde opens the console in Source games).
